# Правила разработки Omarchy Saga Edition

Проект содержит исходники v1.0 для разработки v1.1 и следующих версий.
SagaBoot — Plymouth/QML, fallback hook, UKI/addon и Console Recovery.
SagaLock — визуальный дизайн поверх Lock Explorer; аутентификация остаётся
в штатных PasswordField/LockInput, PAM и session-lock host.
SagaSDDM — независимый greeter; Desktop Reveal — патч compositor Hyprland,
который после настоящего unlock растворяет снимок lock surface за 700 мс.
Подробности: [архитектура](docs/architecture/README.md).

## Git

Все сообщения коммитов, названия и описания Pull Request — на русском языке.
Префиксы feat/fix/docs/chore допустимы. Рабочая основная ветка main; последующие
изменения вести в тематических ветках. Перед коммитом изучать diff и git status,
проверять staged content. Не выполнять push, создавать remote или публиковать
проект без отдельного разрешения. Не переписывать чужую историю и не удалять
неизвестные изменения. Не обновлять hashes ради прохождения проверок.

## Разрешённые записи

По умолчанию менять только этот репозиторий. Установленные каталоги Saga,
~/.config, /usr, /etc, /boot и исходные work-каталоги — только чтение.
Никаких systemctl restart, hyprctl reload, установки пакетов, lock/unlock,
suspend, rebuild initramfs/UKI, reboot или изменений SDDM без отдельного
разрешения пользователя на конкретную процедуру. SummaWay не трогать.
Не читать .ssh, ключи и приватные recovery-данные ради исследования проекта.

## Порядок работы

1. Прочитать [разработку](docs/development/README.md) и происхождение файлов.
2. Сначала выполнить безопасную исходную проверку; затем изменить код и
   повторить затронутые проверки. Не запускать исторические test/install helpers
   вслепую: некоторые управляют runtime или ожидают приватный install-kit.
3. Запустить `python3 -B scripts/test/check-sources.py` и релевантные изолированные
   тесты (`python3 -B scripts/test/run-unit-tests.py`). Для QML нужен Qt6 qmllint,
   для полноценного рендера — изолированная копия зависимостей и offscreen-среда.
4. Сборка Desktop Reveal — только отдельно от системного Hyprland, на точной базе
   из dependencies.json. Никогда не выполнять CMake install в /usr.
5. До установки подготовить reviewable staging, целевые пути, SHA manifest,
   проверенную резервную копию и план отката. Сначала изолированная проверка,
   затем отдельное разрешение на изменение действующей системы.
6. Откат — только проверенными копиями, с остановкой при несовпадении SHA;
   порядок описан в docs/recovery. Не обходить compatibility guard.

Запрещено добавлять EFI/UKI, LUKS/TPM, пароли/токены, личные конфиги, логи
с приватными данными, кэши, сборки, полный upstream и artwork неизвестного
происхождения. Ресурсы без подтверждённых прав оставлять вне Git.
Не назначать проекту лицензию без решения владельца; сохранять лицензии upstream.
